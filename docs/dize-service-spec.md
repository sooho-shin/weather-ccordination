# dize. 서비스 기획서 (Service Specification)

> 본 문서는 Google Slides로 작성된 `dize.` 서비스 기획서 원본 내용을 바탕으로 정리한 공식 기획 명세서입니다.

---

## 01. 서비스 개요 및 핵심 가치

### 서비스 정의
- **서비스명**: `dize.`
- **슬로건**: 미니멀 날씨 & OOTD 웹앱
- **핵심 메시지**: *"복잡한 일기예보 대신, 체감 날씨와 오늘 입을 옷만 보여줍니다"*

### 해결하려는 문제 (Problem)
- 비 오고 쌀쌀한 아침, 옷장 앞에서 5분을 고민한다.
- 일기예보는 숫자를 알려주지만, **무엇을 입어야 하는지는 알려주지 않는다.**
- `dize.`는 **날씨 데이터를 즉각적인 옷차림 행동 지침으로 변환**합니다.

### 핵심 설계 원칙 (Core Principles)
- **원칙 A: 정보의 미니멀화 (No Data Overload)**  
  복잡한 기상 수치 대신, 체감 키워드 뱃지와 최소한의 수치(현재 기온, 최고/최저 기온)만 보여줍니다.
- **원칙 B: 즉각적인 행동 지침 (Actionable OOTD)**  
  보자마자 입을 수 있는 TPO별 실사 코디와 오늘 꼭 챙겨야 할 날씨 방어 아이템을 제시합니다.

## 02. MVP 화면 구조 (1화면 완결형 UX)

회원가입 없이, 첫 화면에서 날씨와 코디를 끝냅니다.

```
┌─────────────────────────────────────────────────────────┐
│ [체감 뱃지] "춥다"  "비온다"                             │
│  9°  (최고 12° / 최저 5°)                               │
│                                                         │
│ [TPO 탭]  [ 출근/단정 ]   [ 데일리/캐주얼 ]   [ 스트릿/힙 ] │
├─────────────────────────────────────────────────────────┤
│                                                         │
│              전신 실사 룩북 이미지                       │
│                                                         │
├─────────────────────────────────────────────────────────┤
│ [날씨 방어 태그]  #우산_필수   #밝은바지_금지               │
│ [코디 셔플 버튼]  "코디 셔플 🔀"                         │
│ [착장 세부 아이템] 아우터 / 상의 / 하의 / 신발            │
└─────────────────────────────────────────────────────────┘
```

1. **온보딩 (Zero-Friction)**
   - 회원가입 없음
   - 위치 권한 허용 및 성별(`남` / `여` / `모두`)만 선택
2. **날씨 상태 영역**
   - 체감 키워드 뱃지 (예: `쌀쌀하다`, `비온다`, `춥다`, `덥다`)
   - 현재 온도 및 최고/최저 기온 노출
3. **OOTD 큐레이션 (TPO 3분할 탭)**
   - **출근 / 단정**: 오피스, 미팅, 포멀 룩
   - **데일리 / 캐주얼**: 편안하고 감각적인 일상 룩
   - **스트릿 / 힙**: 트렌디하고 개성 있는 고프코어/스트릿 룩
4. **아이템 체크리스트 (날씨 방어 태그)**
   - `#우산_필수`, `#밝은바지_금지`, `#일교차_아우터`, `#선글라스_추천` 등 실용적인 행동 가이드
5. **코디 셔플 (Shuffle)**
   - 탭 내에서 랜덤 착장 전환 버튼을 제공하여 매일 같은 화면을 피함

## 03. 4단계 서비스 로드맵 (Roadmap)

### Phase 1: Lean POC (인프라 비용 0원으로 아침 습관 검증)
- **방식**: AI(Midjourney, FLUX)로 고화질 룩북을 미리 생성하여 날씨 조건에 정적으로 매핑
- **에셋 구성**: 6 기온 단계 × 2 성별 × 3 TPO 스타일 = **총 36개 고화질 룩북 에셋**
- **목표**: API/GPU 호출 비용 0원으로 아침 7~9시 필수 방문 습관 형성

### Phase 2: Combinatorial Engine (부위별 조합으로 수만 가지 코디)
- **방식**: 착장을 부위별 누끼(아우터, 상의, 하의, 신발)로 분리하고 알고리즘으로 믹스앤매치
- **목표**: 매일 같은 코디가 나오는 지루함 해소, 수만 가지 조합 확보

### Phase 3: AI Smart Closet & VTO (내 옷장이 곧 전환 비용)
- **방식**: 유저가 자기 옷을 촬영하면 AI가 카테고리/두께/색상을 분류해 디지털 옷장을 생성하고 가상 피팅(VTO) 제공
- **목표**: 타 서비스로 이탈하지 못하도록 전환 비용(Lock-in) 극대화

### Phase 4: Brand Collabs & Commerce (트래픽을 매출로 전환)
- **방식**: TPO에 맞는 패션 브랜드(무신사, 29CM 등)의 스폰서드 코디 노출 및 원클릭 구매 연결
- **목표**: 제휴 수수료와 버추얼 드롭을 통한 본격 수익화 (목표 기업가치: **500억 원**)

## 05. 성장 시나리오 및 경제성 (Unit Economics)

### 36개월 성장 목표
- **6개월 (Phase 1 Lean POC)**: MAU 3만 / DAU 1.2만 (인프라: CDN + 서버리스 무료 티어)
- **12개월 (Phase 2 Engine)**: MAU 10만 / DAU 4만 (인프라: 관리형 DB + 서버리스)
- **24개월 (Phase 3 Closet · PRO 출시)**: MAU 50만 / DAU 20만 / PRO 구독자 2만 명 / 월 구독 2,000만 원 (GPU 추론 도입)
- **36개월 (Phase 4 Commerce)**: MAU 150만 / DAU 60만 / PRO 구독자 7.5만 명 / **월 매출 약 1.8억 원 (연 약 22억 원)**

### 36개월 시점 월 매출 구성
1. **PRO 구독 매출**: **7,500만 원** (7.5만 명 × 1,000원)
2. **커머스 수수료 매출**: **1.1억 원** (MAU 150만 × 구매 전환 1.5% × 객단가 6만 원 × 수수료 8%)
   > *월 1,000원 구독은 모객용 락인 장치이며, 커머스가 전체 매출의 약 60%를 견인*

### PRO 1인당 월 단위 경제성 (Unit Economics)
- **구독료**: `+1,000원`
- **PG 결제 수수료 (약 3%)**: `-30원`
- **AI 생성·추론 비용 목표**: `-400원 이하` *(핵심 관리 지표)*
- **공헌이익**: **약 +570원**

### 기업가치 500억 원 달성 조건
- 시점: 약 60개월 시점
- 지표: MAU 500만 명, 구독 전환율 6%, 커머스 전환율 1.5%
- 실적: 연 매출 약 80억 원 (PSR 약 6배 적용 시 밸류에이션 500억 원 도달)
